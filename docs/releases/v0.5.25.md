Changes since / 相较于 [v0.5.24](https://github.com/daife/Asayn/releases/tag/v0.5.24) (`248a2b5`).

## 更新 / Updates

- 每个持久会话独立保存 `cache_session_id` 和 `prompt_cache_key`；新会话、普通 fork 和独立子 Agent 分别使用自己的缓存标识，压缩临时副本继承原会话标识。
- Persist `cache_session_id` and `prompt_cache_key` per session. New sessions, persistent forks, and independent subagents use distinct identities; temporary compaction copies inherit the original identity.
- 更新中英文说明，明确官方订阅 OAuth Responses 端点、会话缓存标识和服务端缓存命中的区别。
- Document the official subscription OAuth Responses endpoint, session cache identities, and the limits of server-side cache reuse in both READMEs.

## 修复 / Fixes

- 恢复、重试和切换会话时保持缓存路由标识稳定；旧会话从已有 UUID 自动补齐标识，并在下次保存时写入。
- Preserve cache routing identities across restoration, retries, and session switches. Legacy sessions derive missing identities from their existing UUID and persist them on the next save.
- Responses 请求发送稳定的 `session-id` Header；Agent 请求使用持久化的会话缓存 key，替代跨会话共享的 Provider key。
- Send a stable `session-id` header for Responses and use the persisted session cache key for agent requests instead of a provider-wide shared key.
- 使用调用级客户端副本绑定缓存标识，避免共享客户端串用会话标识；保留现有缓存命中统计。
- Bind cache identities to invocation-local client copies so shared clients cannot retain another session's routing identity; retain existing cache usage accounting.

## 验证 / Validation

- `go test ./...`；覆盖 A→A、A→B→A、会话保存恢复、普通 fork 隔离、旧会话兼容和订阅请求缓存字段。
- Tests cover A→A, A→B→A, save/restore, persistent fork isolation, legacy compatibility, and subscription request cache fields.
- 未进行在线缓存命中率实测；稳定标识不保证服务端缓存命中或物理缓存隔离。
- No live cache hit benchmark was performed. Stable identities do not guarantee cache hits or physical cache isolation.
